- 문제: [수열](https://jungol.co.kr/problem/2497)
- 풀이 참고: 없음
- 상태: 🟡 비효율
- 복습필요: Y

## 1. 문제 설명

매일 측정한 온도 N개가 수열로 주어진다. 연속한 K일의 온도 합 중 최댓값을 출력한다. N은 2 이상 100,000 이하, K는 1 이상 N 이하, 온도는 -100 이상 100 이하다. 시간 제한은 0.3초.

## 2. 내 접근 방식

이중 for문으로 갔다. 바깥에서 i를 0부터 N-K까지 밀고 안쪽에서 i부터 i+K까지 더해서 최댓값을 갱신하는 방식이다. 이때 "결국 O(n) 아닌가?"라고 생각했다.

## 3. 틀린 이유

세 번 막혔다.

먼저 시간 초과. 이중 for문은 O((N-K+1) \* K)다. K를 상수처럼 봤는데 K도 100,000까지 가는 입력이었다. 바깥이 줄어드는 만큼 안쪽이 늘어나서 K가 N/2쯤일 때 곱이 최대가 되고, N이 100,000이면 약 2.5 \* 10^9이다. 3초 정도 걸려서 0.3초 제한에 걸렸다.

투포인터로 바꾼 다음엔 갱신 위치를 틀렸다. left를 당기는 while문이 끝나자마자 sum을 answer와 비교했는데, 그러면 윈도우가 아직 K일을 못 채운 초기 구간(right가 K-2 이하)의 합까지 후보로 들어간다. 고정 길이 조건이라 K보다 짧은 구간은 답이 될 수 없다.

그러고도 틀렸는데 answer 초기값을 0으로 둬서였다. 온도가 -100까지 내려가니까 K일 합이 전부 음수인 입력이 있다. 예제 두 개가 다 양수 답(21, 31)이라 로컬에서는 안 걸리고 제출에서 틀렸다.

## 4. 올바른 접근 및 풀이

고정 길이 슬라이딩 윈도우.

right를 한 칸씩 밀면서 sum에 더하고, 길이가 K를 넘으면 left를 당겨 K로 되돌린다. 그리고 길이가 정확히 K일 때만 답을 갱신한다. 초기값은 -Infinity.

```js
let answer = -Infinity;
let left = 0;
let sum = 0;

for (let right = 0; right < N; right++) {
  sum += temperatures[right];

  // 길이가 K보다 크면 left를 +1
  while (right - left + 1 > K) {
    sum -= temperatures[left];

    left++;
  }

  if (right - left + 1 === K && sum > answer) {
    answer = sum;
  }
}
```

각 원소가 sum에 한 번 더해지고 한 번 빠지니까 O(N)이다. N = 100,000, K = 50,000으로 돌려보니 이중 for문 3초에서 0.04초가 됐다.

코드는 같은 폴더의 JUNGOL2497_수열_고정길이슬라이딩윈도우.js에 있다.

## 5. 배운 점

안쪽 루프의 범위가 입력에 비례하는지부터 본다. `for (j = i; j < i + K; j++)`는 K가 상수일 때만 O(1)이다. "바깥이 N-K번밖에 안 도니까 괜찮겠지"가 함정이었다. 바깥이 줄어드는 만큼 안쪽이 늘어난다.

슬라이딩 윈도우도 고정 길이형인지 가변 길이형인지 먼저 정하고 시작한다. 보석 쇼핑 같은 가변 길이형은 조건을 만족하는 상태마다 갱신하지만, 고정 길이형은 길이가 정확히 K인 순간에만 갱신해야 한다. 윈도우 굴리는 코드는 거의 같은데 갱신 조건이 다르다.

최댓값 초기값 0은 "답이 항상 0 이상"이라는 숨은 가정이다. 입력 범위에 음수가 있으면 -Infinity를 쓴다. 최솟값이면 반대로 Infinity.

예제가 통과해도 경계 입력은 직접 만들어 본다. 전부 음수인 입력, K = 1, K = N을 넣어봤으면 제출 전에 잡았다.

길이가 한 번에 1씩만 늘어나니까 저 while은 if로 써도 된다. 가변 길이형 형태에 맞춰 while로 뒀다.
